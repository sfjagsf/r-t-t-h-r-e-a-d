# 28. 传统串口驱动接口：对象、配置与硬件操作表

> 对应源码：`components/drivers/include/drivers/dev_serial.h`。
>
> `rtdevice.h` 在启用 `RT_USING_SERIAL` 且未启用 `RT_USING_SERIAL_V2` 时包含此文件。
> 本文讲解传统串口框架的接口定义；若工程启用了 `RT_USING_SERIAL_V2`，应阅读
> `dev_serial_v2.h`，不能假设两个版本的对象和回调模型完全相同。

## 1. 串口框架的分层位置

```text
应用
  │ rt_device_find/open/read/write/control
  ▼
通用设备框架（components/drivers/core/device.c）
  ▼
传统串口框架（components/drivers/serial/serial.c）
  │ rt_serial_read/write/open、rt_uart_ops
  ▼
BSP UART 驱动
  │ configure / control / putc / getc / dma_transmit
  ▼
UART 硬件、中断与 DMA
```

`dev_serial.h` 不实现串口读写，而是定义串口对象、配置结构、事件、硬件操作表和
注册入口。上层使用通用 `rt_device_t`；串口框架将其转为 `rt_serial_device`；最底层
BSP 则通过 `rt_uart_ops` 接触具体硬件。

## 2. `rtdevice.h` 如何选择串口版本

```c
#ifdef RT_USING_SERIAL
#ifdef RT_USING_SERIAL_V2
#include "drivers/dev_serial_v2.h"
#else
#include "drivers/dev_serial.h"
#endif
#endif
```

| 配置 | 可见的串口接口 |
| --- | --- |
| 未定义 `RT_USING_SERIAL` | 不包含串口驱动接口 |
| `RT_USING_SERIAL` | 传统串口接口 `dev_serial.h` |
| `RT_USING_SERIAL` + `RT_USING_SERIAL_V2` | 新版串口接口 `dev_serial_v2.h` |

本章的代码与对象均针对传统接口。

## 3. 串口通信参数与默认配置

文件定义了常用通信参数，例如：

```c
BAUD_RATE_115200
DATA_BITS_8
STOP_BITS_1
PARITY_NONE
BIT_ORDER_LSB
NRZ_NORMAL
```

`STOP_BITS_1` 的值为 `0`、`STOP_BITS_2` 的值为 `1`，它们是框架的枚举编码，不能将
底层数值直接理解为停止位数量。

默认配置宏为：

```c
RT_SERIAL_CONFIG_DEFAULT
```

默认语义：

| 项目 | 默认值 |
| --- | --- |
| 波特率 | 115200 bit/s |
| 数据位 | 8 位 |
| 停止位 | 1 位 |
| 校验 | 无校验 |
| 位序 | LSB 优先 |
| 反相 | 关闭 |
| 接收软件缓冲区 | `RT_SERIAL_RB_BUFSZ` |
| 硬件流控 | 关闭 |

`RT_SERIAL_RB_BUFSZ` 未被工程配置覆盖时为 64 字节。BSP 往往以
`.config = RT_SERIAL_CONFIG_DEFAULT` 初始化串口对象，之后再经控制命令和硬件
`configure` 回调调整。

## 4. `struct serial_configure`：当前串口配置

```c
struct serial_configure
{
    rt_uint32_t baud_rate;
    rt_uint32_t data_bits   :4;
    rt_uint32_t stop_bits   :2;
    rt_uint32_t parity      :2;
    rt_uint32_t bit_order   :1;
    rt_uint32_t invert      :1;
    rt_uint32_t bufsz       :16;
    rt_uint32_t flowcontrol :1;
    rt_uint32_t reserved    :5;
};
```

| 字段 | 含义 |
| --- | --- |
| `baud_rate` | 波特率 |
| `data_bits` | 数据位数 |
| `stop_bits` | 停止位数量 |
| `parity` | 无、奇或偶校验 |
| `bit_order` | 位发送顺序 |
| `invert` | 是否使用反相 NRZ |
| `bufsz` | 接收软件缓冲区长度 |
| `flowcontrol` | 是否启用 CTS/RTS 流控 |

其中除 `baud_rate` 外大多采用位域以节省存储空间。驱动应使用字段语义，而不应依赖
其在内存中的具体位排列。

## 5. 接收、发送模式与事件

串口可以使用轮询、中断或 DMA。

```text
轮询接收：CPU 主动检查状态并取接收寄存器
中断接收：收到字符触发 IRQ，框架转存到软件 FIFO
DMA 接收：DMA 将 UART 数据搬入内存，完成或超时后通知

轮询发送：逐字调用 putc
中断发送：TX 空中断持续发送数据
DMA 发送：DMA 搬运一整段发送缓冲区
```

相关模式宏：

```c
RT_SERIAL_RX_INT
RT_SERIAL_TX_INT
RT_SERIAL_DMA_RX
RT_SERIAL_DMA_TX
```

中断服务程序向串口框架报告的事件：

| 事件 | 含义 |
| --- | --- |
| `RT_SERIAL_EVENT_RX_IND` | 收到数据，可从 UART 取字符 |
| `RT_SERIAL_EVENT_TX_DONE` | 普通发送完成 |
| `RT_SERIAL_EVENT_RX_DMADONE` | DMA 接收完成 |
| `RT_SERIAL_EVENT_TX_DMADONE` | DMA 发送完成 |
| `RT_SERIAL_EVENT_RX_TIMEOUT` | 接收超时，常用于帧边界判断 |

BSP 应在识别到硬件事件后调用：

```c
rt_hw_serial_isr(serial, event);
```

而不是在每个 BSP 的 ISR 中重复实现软件 FIFO、上层通知等框架逻辑。

## 6. 接收与发送运行期状态

### 6.1 接收 FIFO

```c
struct rt_serial_rx_fifo
{
    rt_uint8_t *buffer;
    rt_uint16_t put_index, get_index;
    rt_bool_t is_full;
};
```

这是软件环形缓冲区：UART 中断将字符写入 `buffer[put_index]`，应用的
`rt_device_read()` 从 `buffer[get_index]` 取走字符。

```text
put_index == get_index，is_full == RT_FALSE → 空
put_index == get_index，is_full == RT_TRUE  → 满
```

### 6.2 发送 FIFO 与 DMA 状态

```c
struct rt_serial_tx_fifo
{
    struct rt_completion completion;
};
```

`completion` 用于同步等待发送完成。

```c
struct rt_serial_rx_dma
{
    rt_bool_t activated;
};

struct rt_serial_tx_dma
{
    rt_bool_t activated;
    struct rt_data_queue data_queue;
};
```

`activated` 标记 DMA 路径是否在运行；发送 DMA 使用 `data_queue` 保存待发送数据块，
使异步发送可以持续排队。

## 7. 串口对象 `struct rt_serial_device`

```c
struct rt_serial_device
{
    struct rt_device          parent;
    const struct rt_uart_ops *ops;
    struct serial_configure   config;
    void *serial_rx;
    void *serial_tx;
    struct rt_spinlock spinlock;
    struct rt_device_notify rx_notify;
};
```

| 成员 | 含义 |
| --- | --- |
| `parent` | 让串口作为通用 `rt_device` 使用 |
| `ops` | BSP 提供的 UART 硬件操作表 |
| `config` | 当前串口通信配置 |
| `serial_rx` | 指向接收 FIFO 或 DMA 运行期状态 |
| `serial_tx` | 指向发送 completion 或 DMA 队列 |
| `spinlock` | 保护并发访问的运行期状态 |
| `rx_notify` | 接收通知封装对象 |

启用 `RT_USING_SERIAL_BYPASS` 时还会包含 `bypass` 成员。

对象嵌入关系：

```text
具体 BSP UART 对象
  └─ struct rt_serial_device
       └─ struct rt_device parent
```

因此具体 UART 可以注册为 `uart1`、`uart2` 等名称，并被应用作为 `rt_device_t` 查找。

## 8. 硬件操作表 `struct rt_uart_ops`

```c
struct rt_uart_ops
{
    rt_err_t (*configure)(struct rt_serial_device *serial,
                          struct serial_configure *cfg);
    rt_err_t (*control)(struct rt_serial_device *serial,
                        int cmd, void *arg);
    int (*putc)(struct rt_serial_device *serial, char c);
    int (*getc)(struct rt_serial_device *serial);
    rt_ssize_t (*dma_transmit)(struct rt_serial_device *serial,
                               rt_uint8_t *buf, rt_size_t size,
                               int direction);
};
```

这是串口框架与芯片相关 BSP 驱动的边界。

| 回调 | BSP 驱动职责 |
| --- | --- |
| `configure` | 设置波特率、数据位、停止位、校验和流控寄存器 |
| `control` | 启停 RX/TX 中断、DMA，或处理其他 UART 控制命令 |
| `putc` | 向硬件发送寄存器写入一个字符 |
| `getc` | 从硬件接收寄存器读取一个字符；无数据时通常返回负值 |
| `dma_transmit` | 配置并启动 DMA 发送 |

串口框架负责通用 `read/write/open/control` 逻辑与缓冲管理；BSP 驱动只需实现这些
硬件相关操作。

## 9. ISR 与上层接收通知

典型通知链：

```text
UART 中断
→ BSP 判断硬件中断来源
→ rt_hw_serial_isr(serial, event)
→ 串口框架更新 FIFO/DMA 状态
→ 调用 dev->rx_indicate 或 dev->tx_complete
→ 上层线程获知“可读”或“发送完成”
```

`rx_indicate` 只代表“有数据可处理”，不表示已收到完整协议帧。回调可能运行于中断或
DMA 完成上下文，应只做轻量动作，例如释放信号量、发送事件或投递消息；协议解析应放在
被唤醒的线程中进行。

## 10. 注册入口与使用方式

传统串口设备的 BSP 注册入口为：

```c
rt_err_t rt_hw_serial_register(struct rt_serial_device *serial,
                               const char *name,
                               rt_uint32_t flag,
                               void *data);
```

使用时，BSP 通常先填写 `ops` 和默认配置，再注册：

```c
serial.ops = &uart_ops;
serial.config = RT_SERIAL_CONFIG_DEFAULT;

rt_hw_serial_register(&serial,
                      "uart1",
                      RT_DEVICE_FLAG_RDWR | RT_DEVICE_FLAG_INT_RX,
                      &uart_private_data);
```

应用的典型使用流程：

```c
serial = rt_device_find("uart1");
rt_device_open(serial, RT_DEVICE_FLAG_INT_RX);
rt_device_set_rx_indicate(serial, uart_rx_callback);

rt_device_write(serial, 0, "hello\r\n", 7);
/* 在被 rx_indicate 唤醒的线程中调用 rt_device_read() */
```

`rt_hw_serial_register_tty()` 面向 TTY 整合场景；普通 MCU BSP 初始化最常使用
`rt_hw_serial_register()`。

## 11. 本章小结

1. `dev_serial.h` 是传统串口框架的接口定义，串口 V2 工程应改读 `dev_serial_v2.h`；
2. `rt_serial_device` 通过内嵌 `rt_device` 接入通用设备框架；
3. `serial_configure` 保存当前通信参数，`RT_SERIAL_CONFIG_DEFAULT` 给出 115200 8N1 等默认值；
4. `rt_uart_ops` 是串口框架与芯片相关 BSP 驱动的硬件边界；
5. BSP 用 `rt_hw_serial_isr()` 上报 IRQ/DMA 事件，框架再维护缓冲和异步通知；
6. `rt_hw_serial_register()` 将具体 UART 注册为可被 `rt_device_find("uart1")` 查找的设备。

下一节阅读 `components/drivers/serial/dev_serial.c`，可看到这些对象和回调如何被真正接入
通用 `rt_device` 的 `open/read/write/control` 流程。
